# Kirana Store Manager

## Overview

Full-stack AI-powered shop management web app for Indian kirana (grocery) store owners. Multi-tenant SaaS — one shop can have multiple users (owner/admin/staff). Mobile-first React frontend with an Express API backend and PostgreSQL database.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **Frontend**: React + Vite (artifacts/kirana-store)
- **API framework**: Express 5 (artifacts/api-server)
- **Database**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec at `lib/api-spec/openapi.yaml`)
- **Build**: esbuild (ESM bundle)
- **PDF generation**: pdfkit (styled blue-theme invoices)
- **WhatsApp**: Twilio API (graceful no-op if TWILIO_* env vars missing)
- **State**: Zustand (auth + language)
- **Charts**: Recharts

## Architecture

### Multi-Tenant Model
- Every user belongs to a **shop** (1 shop per registration, multi-user support via `shop_members`)
- JWT tokens contain `{ userId, shopId }` — all data is scoped by `shopId`
- All IDs are UUIDs (uuid v4 generated by PostgreSQL `gen_random_uuid()`)
- `authMiddleware` in `auth.ts` loads user + shop + membership and attaches to `req`

### DB Tables (all with UUID PKs)
- `users` — user accounts
- `shops` — shop profiles (name, phone, address, ownerUserId)
- `shop_members` — many-to-many: user↔shop with role (owner/admin/staff)
- `items` — inventory items scoped by shopId
- `invoices` — billing records with JSONB items array, customerPhone, customerId
- `customers` — customer directory scoped by shopId
- `labour` — workers scoped by shopId
- `attendance` — daily attendance records (shopId + labourId + date + status)
- `notifications` — in-app alerts scoped by shopId

## Features

1. **Authentication** — JWT-based login/register; registration creates shop + membership automatically
2. **Inventory Management** — Add/edit/delete items; 30 preloaded kirana defaults via `/items/seed-defaults`; low-stock alerts
3. **Billing/Invoice System** — Create invoices, auto-deduct stock, Cash/UPI payment modes, customer phone for WhatsApp
4. **PDF Invoices** — Blue-theme styled PDF via pdfkit at `/api/invoices/:id/pdf`
5. **WhatsApp Delivery** — Auto-sends PDF URL via Twilio after invoice creation (if TWILIO_* set)
6. **Customer Management** — Full CRUD for customer directory at `/customers`
7. **AI OCR** — Parse image text into invoice items (fuzzy match to inventory; Hindi/English)
8. **AI Voice Input** — Parse spoken text into invoice items
9. **Labour Management** — Add workers, mark daily attendance, auto-calculate monthly salary
10. **Dashboard & Analytics** — Daily/monthly sales, profit estimation, low-stock alerts, top items, customer count

## Key Files

- `lib/db/src/schema/` — All Drizzle table schemas (UUID PKs, shopId foreign keys)
- `lib/api-spec/openapi.yaml` — OpenAPI v0.2.0 spec (source of truth for codegen)
- `lib/api-zod/src/index.ts` — Must stay as single `export * from "./generated/api";`
- `artifacts/api-server/src/lib/auth.ts` — UUID JWT + authMiddleware + getUser/getShop helpers
- `artifacts/api-server/src/lib/pdf.ts` — PDF generator (generateInvoicePdf) + Twilio WhatsApp sender
- `artifacts/api-server/src/routes/` — All route handlers (items, invoices, customers, labour, attendance, notifications, analytics, ai, auth)
- `artifacts/kirana-store/src/pages/customers.tsx` — Customer CRUD page
- `artifacts/kirana-store/src/pages/billing.tsx` — Billing with customerPhone for WhatsApp

## Environment Variables / Secrets

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string (auto-provided by Replit) |
| `SESSION_SECRET` | Session signing secret |
| `TWILIO_ACCOUNT_SID` | Twilio SID for WhatsApp (optional) |
| `TWILIO_AUTH_TOKEN` | Twilio auth token (optional) |
| `TWILIO_WHATSAPP_FROM` | Twilio WhatsApp number e.g. `+14155238886` (optional) |

## Development Notes

- To regenerate API types after editing `openapi.yaml`: `pnpm --filter @workspace/api-spec run codegen` then restore `lib/api-zod/src/index.ts` to single export
- To reset DB: drop tables in `executeSql` sandbox, then run `pnpm --filter @workspace/db run push`
- The build externalizes `@swc/core` and `@swc/cli` but bundles `@swc/helpers` (needed by pdfkit→fontkit)
- All ID function params in routes are `string` (UUID), not `number` — never use `parseInt()`
- `getShop(req)` gives the authenticated shop; use `shop.id` for all data scoping
